# workspace-rail

workspace-rail 是面向 Windows 上 Stencil Tern 0.9.7 的工作区插件，可在 Tern 中查看和打开项目、Git 工作树及会话，并通过向导添加项目或管理工作树。它既可用于本机，也可用于已连接的 Tern 远程主机。本文不声明其他 Tern 版本或操作系统的兼容性。

侧栏本身是一个 Tern pane，不是真正的窗口级固定侧栏。它参与正常的 pane 布局，可以用命令重新打开或关闭。

## 前置条件

- Windows 上的 Stencil Tern 0.9.7。
- 在执行项目操作的主机上安装 Git，并确保 Tern 启动的进程能从 `PATH` 找到 `git`。本机和每台远程主机各自使用自己的 Git。
- Windows 主机扫描普通文件夹中的嵌套仓库时，需要能够运行系统 PowerShell。
- 新建 Git 项目会创建一次空的初始提交。请事先在目标主机配置 Git 的 `user.name` 和 `user.email`，否则首次提交会失败。
- 克隆私有仓库时，首次连接或认证可能需要在目标主机配置 Git 凭据助手或可用的 SSH 密钥。

## 安装

在本机命令行中，将插件目录链接到 Tern。请将 `<本目录>` 替换为包含 `plugin.toml` 的实际目录，路径中有空格时保留引号：

```powershell
tern plugin link "<本目录>"
```

Tern 会从该目录加载插件。若要管理远程主机，除本机安装外，还必须在每台目标主机上单独安装并启用同一插件的 host 部分。在远程主机的 Tern pane 中，使用该主机上已有的插件目录安装：

```powershell
tern plugin install "<远程主机上的插件目录>"
```

先通过 Tern 连接远程主机，首次连接时按 Tern 提示核对并信任主机指纹。只有已连接的主机才能用于打开项目或向导；侧栏可显示访问过的离线主机缓存，但不能对离线主机执行操作。项目记录分别保存在所属主机上。远程路径、Git、文件和凭据都属于远程主机，不会交给本机 Git 处理。

## 打开和关闭侧栏

在 Tern 命令面板运行 **Workspace Rail: Toggle Sidebar**。再次运行同一命令可关闭侧栏。也可以运行 **Workspace Rail: Add Project** 直接打开添加项目向导。

添加项目的默认快捷键是 `Ctrl+Alt+Shift+A`；侧栏切换没有默认快捷键，可通过命令面板操作。也可在 Tern 设置的 `keybinds` 中为 `plugin.workspace-rail.toggle_sidebar` 和 `plugin.workspace-rail.add_project` 自定义快捷键。

侧栏支持按主机名、项目名、工作树名、分支名或路径搜索，也可选择主机。点击工作树行或普通文件夹的主目录行，可在对应目录打开会话；也可以用上下方向键选择行，再按回车打开。

## 侧栏行和操作

「全部」下以紧凑的扁平行显示工作树，无需展开项目。每行有状态标记、带文件夹图标的项目标记和分支名；没有分支名时显示工作树名。当显示名称与项目名相同时，项目标记只显示文件夹图标，避免重复。Git 主工作树标记为「主要」，普通文件夹的主目录标记为「主目录」；锁定、目录缺失和已注销状态也会在行上标出。

将鼠标移到行上、让行内控件获得焦点，或用键盘选中行时，右侧会显示可用操作：

- Git 项目的 `+` 打开新建工作树向导；Git 项目和普通文件夹的 `−` 用于移除项目记录。项目操作位于其主工作树或主目录行；如果主行未显示，则位于第一个可见的工作树行。项目显示「正在读取…」「读取失败」或「没有工作树」的占位行时，操作显示在占位行上。
- 非主 Git 工作树行的 `×` 打开删除工作树的确认界面；主工作树没有该删除操作。移除项目记录也需要确认。

## 添加项目

从侧栏选择添加项目，或从命令面板打开 **Workspace Rail: Add Project**，然后选择已连接的目标主机：

- **现有文件夹**：浏览并选择目录。目录本身是 Git 仓库或位于仓库内时，使用仓库根目录；普通目录会扫描其中的仓库，可选择要添加的仓库，也可添加普通文件夹。
- **克隆**：填写仓库 URL、目标父目录和项目名。目标目录必须不存在，插件不会覆盖已有目录。
- **新建 Git 项目**：填写目标父目录和项目名。目标目录必须不存在；插件初始化仓库并创建空的初始提交。

添加、克隆或新建成功后会打开项目。多选仓库时，向导打开第一个添加成功的项目。

普通文件夹的仓库扫描最多深入 8 层、接受 512 个候选仓库，不跟随符号链接或目录联接，并跳过 `.git`、`node_modules`、`build`、`dist`、`target`、`out`、`.next` 和 `.venv`。超过候选上限时会显示错误，可选择范围更小的目录重新扫描。

在 Windows 上，新建和克隆的默认父目录为目标主机的 `USERPROFILE` 下的 `tern/projects`；若未设置 `USERPROFILE`，则使用 `HOME`。两者都未设置时，父目录初始为空，需要自行填写。默认父目录不存在时，提交操作会创建它；其他父目录必须已存在。输入的所有路径都应是所选主机上的路径。

## 工作树

在 Git 项目上选择新建工作树，填写新分支、工作树路径和可选的基准。默认路径是在项目路径后加 `-` 和分支名，其中分支名里的 `/`、`\` 会换成 `-`，也可以修改。例如，项目 `D:\code\app` 的 `feature/new-ui` 分支默认使用 `D:\code\app-feature-new-ui`。每次新建会创建一个新分支；同一个分支不能同时检出到多个工作树。

侧栏允许删除非主工作树，并要求确认。删除使用普通的 `git worktree remove`，不强制删除，也不会删除分支；主工作树不能通过此操作删除。请在删除前备份需要保留的文件：**Git 可能在删除工作树时一并删除被忽略的文件**，即使这些文件不会使工作树显示为有未提交的更改。

在 Windows 上，如果工作树仍被终端或其他程序占用，Git 可能已注销该工作树，却留下磁盘上的空目录。此时侧栏会显示「已注销」和删除失败信息。结束占用该目录的会话或程序后，可以重试删除。对于已注销的工作树，插件只会删除空的残留目录；如果目录中仍有文件或子目录，插件会保留目录并提示，不会递归或强制删除。分支会保留。

侧栏的移除项目只移除项目记录，不删除磁盘上的项目或工作树。

## 错误与数据安全

目录、Git 和认证错误会显示在界面中。插件不会强制清理已有或失败操作留下的目录；创建或克隆失败时，目标目录可能留有数据，请先查看错误和实际内容，再决定如何处理。删除工作树失败时错误会保留并显示，可能仍有目录留在磁盘上。插件不会通过强制删除来掩盖这些错误。

## 卸载

如果按上面的方式链接了本机插件，运行：

```powershell
tern plugin unlink workspace-rail
```

这会移除链接，不会删除插件目录。如果在远程主机使用 `tern plugin install` 安装了副本，请在该主机的 Tern pane 中运行：

```powershell
tern plugin remove workspace-rail
```

各主机需要分别卸载。移除插件不会删除项目文件；Tern 会保留插件数据，重新安装时可再次使用已有记录。
